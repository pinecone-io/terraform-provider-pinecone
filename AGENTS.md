# AGENTS.md

Guidance for AI coding agents working in this repository. For human-facing setup
details, see [CONTRIBUTING.md](CONTRIBUTING.md) and [README.md](README.md).

## Overview

This is the Terraform Provider for Pinecone (`pinecone-io/pinecone` on the Terraform
Registry). It's written in Go on the
[Terraform Plugin Framework](https://developer.hashicorp.com/terraform/plugin/framework)
and talks to Pinecone through the Go SDK, `github.com/pinecone-io/go-pinecone/v7`.

It manages indexes, collections, projects, API keys, service accounts, users,
invites, and role bindings.

## Repository layout

| Path | Contents |
| --- | --- |
| `main.go` | Provider entry point and the `go:generate` directives for docs. |
| `pinecone/provider/` | Provider, resources (`*_resource.go`), and data sources (`*_data_source.go`, plural for list data sources). Shared helpers live in `common.go`. |
| `pinecone/models/` | Terraform state/plan models (`tfsdk`-tagged structs) and conversions to and from SDK types. |
| `examples/` | Terraform examples that feed the generated docs. `examples/README.md` lists which paths the docs tool reads. |
| `templates/` | `tfplugindocs` templates (e.g. the v5 upgrade guide). |
| `docs/` | **Generated** Registry docs. Don't edit by hand. |
| `scripts/sync_to_public.sh` | Maintainer script that syncs the private mirror to the public repo. |
| `scratch/` | Gitignored local notes. |

## Commands

Requirements: Go (version in `go.mod`), Terraform >= 1.4.6, and golangci-lint
**v2.12.2** to match CI.

```sh
go build ./...                 # build
go test ./pinecone/...         # unit tests, no credentials needed
golangci-lint run              # lint, same config as CI
go generate ./...              # format examples and regenerate docs/
just fmt                       # gofmt all Go files
```

Before considering a change done, run all of: `go build ./...`,
`go test ./pinecone/...`, `golangci-lint run`, and `go generate ./...`. CI runs
each of them, and `go vet` / `go test` alone won't catch lint failures such as
`forcetypeassert` or `godot` (comments must end with a period).

### Acceptance tests

Acceptance tests (`resource.Test` cases) create **real resources in Pinecone** and
may incur costs. They're skipped unless `TF_ACC=1` is set. Don't run them unless
the user asks you to.

```sh
export PINECONE_API_KEY=... PINECONE_CLIENT_ID=... PINECONE_CLIENT_SECRET=... PINECONE_PROJECT_ID=...
TF_ACC=1 go test -timeout 15m -v ./pinecone/provider/ -run TestAccIndexResource
```

`just testacc` runs the full suite (`TF_ACC=1 go test ./... -v -timeout 120m`).
Always narrow with `-run` when you can.

Tests that only check plan-time validation can run without credentials by using
the dummy provider configs in `provider_test.go`
(`testAccDummyApiKeyProviderConfig`, `testAccDummyAdminProviderConfig`).

## Generated docs

`docs/` is generated by `tfplugindocs` from the provider schema
(`MarkdownDescription` fields), `examples/`, and `templates/`. Whenever you change
a schema description, an example, or a template, run `go generate ./...` and
include the resulting `docs/` changes. CI fails if `docs/` is out of date.

`go generate` passes `--provider-name terraform-provider-pinecone` explicitly, so
it works from git worktrees whose directory name differs from the repo name.

## Code conventions

- Match the surrounding code: its naming, comment density, and idiom.
- Resources and data sources embed `PineconeResource` / `PineconeDatasource` from
  `common.go`, which provide `client` (API key) and `adminClient` (client
  ID/secret). Admin resources (projects, API keys, service accounts, users,
  invites, role bindings) use `adminClient`.
- Keep Terraform models and SDK conversions in `pinecone/models/`; keep schema,
  CRUD, and plan logic in `pinecone/provider/`.
- Use the helpers in `common.go` instead of reimplementing them: `isNotFoundErr` /
  `isConflictErr` (match on `*pinecone.PineconeError` status codes, not error
  strings) and `retryDeletion` for async admin deletes.
- On `Read`, a not-found error means the resource was deleted out of band: remove
  it from state rather than erroring.
- Prefer catching invalid configurations at plan time (validators,
  `ValidateConfig`, `ModifyPlan`) over failing at apply.
- Use checked type assertions (`v, ok := x.(T)`); `forcetypeassert` is enabled.
- Every schema attribute needs a `MarkdownDescription`; it becomes the Registry docs.

### `pinecone_index`

The index resource is the most complex part of the provider. It supports two
mutually exclusive configuration styles:

- **`schema` style** (`schema`, `deployment`, top-level `read_capacity`): matches
  Pinecone API version `2026-07`. Use it for new functionality. Logic lives in
  `index_resource_schema_mode.go`, with models in
  `pinecone/models/index_schema.go` and `index_resource_schema.go`.
- **`spec` style** (`dimension`, `metric`, `vector_type`, `spec`, `embed`): the
  legacy style, planned for deprecation. It's still required for legacy integrated
  indexes and pod-based indexes.

Style detection and the one-way `spec` → `schema` migration live in
`index_resource_style.go`. Changes to index behavior usually need updates to the
README's index section, the example in `examples/resources/pinecone_index/`, and
possibly the v5 upgrade guide template.

## Compatibility

This is a published provider with users' state files depending on it. Treat
these as breaking changes and call them out to the user before making them:

- Removing or renaming an attribute, or changing its type.
- Changing an attribute from in-place update to `RequiresReplace`.
- Changing how existing state is read, so that a plan shows a diff with no config change.

## Git and release workflow

- Development happens in a **private mirror**. Changes merged to the mirror's
  `main` are fast-forwarded to the public repo with `scripts/sync_to_public.sh`.
  Never merge pull requests in the public repo, and don't run the sync script or
  push tags unless the user explicitly asks.
- Releases are cut by tagging `vX.Y.Z` on the public repo; GoReleaser handles the
  rest (`.goreleaser.yml`, `.github/workflows/release.yml`).
- Don't commit or push unless asked.
- Never commit credentials. `.env` is gitignored for local secrets.
